Prompt 1（首次调研，需求澄清）
我想做一个AI辅助舞蹈教学评分平台，针对敦煌舞。请帮我梳理当前舞蹈AI评分领域的主流技术路线，对比以下几种姿态提取方案的优劣势：MediaPipe Pose、OpenPose、YOLOv8-Pose、MMPose。同时请分析动态时间规整（DTW）在姿态序列对齐中的应用现状，特别是带Sakoe-Chiba带宽约束的精确DTW与FastDTW近似算法的差异。

方案对比表：MediaPipe 速度快（单帧~10ms）、轻量（~1MB）、33个关键点稳定；OpenPose 精度高但慢；YOLOv8-Pose 端到端但关键点数量固定；MMPose 可配置但依赖重
DTW 带宽：Sakoe-Chiba带宽约束可防止对齐路径发散，但带宽窗口j≈i的传统设置对长视频时长差不友好，建议用缩放对角线 j_c = i×m/n 为中心

Prompt 2（核心代码脚手架）
用Python写一个基于MediaPipe Pose的舞蹈视频姿态提取与评分脚本。输入是两个mp4视频（teacher.mp4和student.mp4），输出学生视频相对于教师视频的相似度评分。需要用DTW对齐两个姿态序列，然后计算关节角度差异。请给出完整函数签名、参数说明和核心逻辑。
AI 初版输出的核心代码片段（简化）
# AI生成版本（有问题）&#10;import mediapipe as mp&#10;import cv2&#10;&#10;def extract_pose(video_path):&#10;    mp_pose = mp.solutions.pose.Pose()  # ← 每次调用新建&#10;    cap = cv2.VideoCapture(video_path)&#10;    keypoints = []&#10;    while cap.isOpened():&#10;        ret, frame = cap.read()&#10;        if not ret: break&#10;        results = mp_pose.process(frame)&#10;        if results.pose_landmarks:&#10;            keypoints.append([(lm.x, lm.y) for lm in results.pose_landmarks.landmark])&#10;    return keypoints
学生审查后发现的3个关键Bug与修复
Bug 1：跨视频Pose对象复用导致状态串扰——AI每次extract_pose新建Pose()看似正确，但MediaPipe Pose内部有跨帧追踪状态（tracking_state），实际运行时第二个视频会沿用第一个视频的追踪状态，导致相同输入视频两次提取结果不一致。学生独立改为：用with语句配合sessions，每次处理新视频前显式重建Pose对象并强制reset()
Bug 2：DTW带宽窗口设置不当——AI默认用Sakoe-Chiba带宽中心为j≈i（固定对角线），当教师与学生视频时长差超过30%时，最优对齐路径被挤出带宽窗口，节奏掌握度返回0分。学生独立改为缩放对角线 j_c = i×m/n，并增加±450ms分段偏移搜索
Bug 3：OpenCV默认mp4v编码导致浏览器无法播放——AI初版用cv2.VideoWriter默认mp4v编码器，浏览器解码失败显示黑屏。学生独立改为调用ffmpeg subprocess输出H.264编码，并统一转码为720p30fps
