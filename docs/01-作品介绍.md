一、作品定位
1.1 作品概述
“舞韵敦煌”是一套面向少儿艺术培训机构的敦煌舞教学与运营一体化平台。系统由管理端、教师端、学员端三端业务系统与 AI 舞蹈评分引擎共同组成：业务侧覆盖课程与排课、报名缴费、考勤、作业、考级比赛、调课审批、运营统计等培训机构的完整业务链；教学侧面向敦煌舞场景，提供教师参考视频与学员练习视频的自动评分、分部位诊断、节奏对齐分析、骨架叠加对比与 AI 语义点评。
作品以“让舞蹈教学反馈可量化、可解释、可复现”为目标，将姿态估计、动态时间规整（DTW）、音频节拍分析与多模态大模型组合为一条可落地的评分流水线，并把评分结果嵌入真实的教务与作业流程，而不是停留在一个孤立的算法演示程序上。
系统采用前后端分离架构：Spring Boot 提供统一 REST 接口与基于 JWT 的权限控制，Vue 3 构建三端界面，MySQL 8 存储业务数据，Python FastAPI 服务独立承担视频预处理、姿态提取、时序对齐与评分，豆包视觉大模型在量化评分基础上生成教学语言点评。

1.3 解决的关键问题
• 人工逐帧比对师生视频效率低、反馈依赖教师经验，难以规模化；系统以统一的量化口径自动生成评分。
• 只给一个总分无法指导改进；系统输出 6 个身体部位 × 3 个评价维度的细粒度得分，并定位最差关键帧。
• 师生视频时长、节奏、起拍位置往往不一致，直接逐帧比较会失真；系统采用带 Sakoe-Chiba 带宽约束的 DTW 做时序对齐。
• 量化分数缺少教学语言；系统引入豆包视觉模型，在量化上下文约束下生成四段式点评与可执行建议。
• 机构业务数据分散在表格与聊天记录中；系统以 47 张业务表统一承载，并建立三端隔离的知识库与可执行智能体。
二、作品创新
2.1 双通道评分：既“打得分”，也“讲得清”
通道一为几何量化通道：MediaPipe Pose 提取 33 个关键点，计算关节角度序列，经 DTW 对齐后按 6 个身体部位与动作规范度、节奏掌控度、完成度 3 个维度评分，再由 12 维特征经 Ridge 回归校准到专家评分口径。通道二为语义增强通道：从教师与学生视频中各抽取 6 张关键帧，连同通道一的量化结果与知识库教学要点，送入豆包视觉模型，生成教师分析、学员分析、节奏一致性判断与 3 条改进建议。
两条通道职责清晰：量化通道保证可复现与可比较，语义通道负责把数字翻译成教学语言；语义通道不得修改量化分数，避免大模型“幻觉”污染评分结果。
2.2 节奏对齐：把“踩拍”变成可量化指标
系统从视频中抽取音轨并跟踪音乐节拍，同时以关键点位移能量峰值检测动作节拍，在 ±150 ms 容差内计算命中率、平均偏差与速度一致性。针对舞蹈中常见的半速踩拍与舞者相位游走，引入半速感知网格与分段相位精化：先做全局偏移搜索，再按 10 秒窗口独立选择局部最优偏移。真实提交数据验证，节奏命中率由 25.17% 提升至 69.44%，节奏得分由 50.12 提升至 75.20。
2.3 敦煌舞动作资产与数字展馆
作品将公开舞蹈数据集中的动作序列转化为可复用的敦煌舞动作资产：以 FineDance 数据集中 203 段有效动作序列（含敦煌舞 2 段、汉唐舞 13 段、身韵舞 40 段、民族舞 63 段）为基础，训练 MLP 自编码器，并对两段敦煌舞序列做定向精调，重建 MSE 分别达到 0.00056 与 0.00112，在全部序列中拟合效果排名前二。在此基础上实现敦煌数字展馆，支持八类标志性动作的零依赖 Canvas 骨架回放、缩放旋转与关键姿态展示。
2.4 三端知识库与可执行智能体
知识库按管理端、教师端、学员端三个角色域隔离存储，通过唯一索引实现幂等归集，业务操作会自动触发知识归集且失败不阻断主流程。AI 问答优先检索知识库再生成回答，并完整记录调用日志。智能体（Agent）以工具调用方式执行“创建课程、调课申请、调课审批”等真实业务操作，工具内部做归属链校验，敏感操作执行前必须经用户二次确认，形成“能查、能做、可追溯”的闭环。
2.5 工程可靠性设计
• 五路视频同步采用单一主时钟单向广播，播放过程不写回 currentTime，避免进度回退与抖动。
• 视频资源 URL 追加时间戳并配置强制回源，规避原地替换文件造成的浏览器缓存分段错乱。
• 上传上限 1024 MB、前端超时 10 分钟，满足标准动作视频的大文件上传。
• 评分结果持久化缓存，同一提交重复打开直接返回结果，仅在显式强制重评时重新计算。
• 评分任务向 Java 后端透出各阶段进度，前端以条纹进度条与阶段文案实时反馈。

3.3 数据库设计
数据库采用第三范式设计，围绕“用户—角色—业务实体”组织。当前交付库共 47 张表，覆盖系统用户、教师、学员、课程、班级、排课、报名、缴费、考勤、作业、考级、调课、知识库、AI 模型、智能体会话、调用日志等主题。设计要点如下：
• 实体完整性与参照完整性：主键统一自增，业务编号（教师号、学号）设唯一索引；核心业务表建立外键约束。
• 用户自定义完整性：性别、状态、金额、时间区间等字段设置 CHECK 或应用层校验，关键枚举以字典表维护。
• 性能设计：排课冲突检测使用“教室 + 日期 + 时段”复合索引；考勤使用“班级 + 学员 + 日期”唯一键防重；订单与日志按时间字段建索引。
• 数据库对象：设计视图统计课程出勤率，使用触发器联动考勤计数，并提供存储过程与统计查询支撑报表。
• 评分报告以 JSON 字段存储结构化结果，既保留算法细节，又避免为每个指标新增列导致表结构膨胀。

3.5 评分模型与校准
部位权重不采用固定值，而是根据参考动作的关节活动幅度动态推断，避免“手臂动作多的舞段”被腿部权重稀释。校准模型以 12 维特征（6 个部位分、3 个维度分、DTW 距离、节奏成本、原始总分）为输入，以专家评分为目标，使用 Ridge 回归拟合。100 组样本中 20 组作为测试集，平均绝对误差（MAE）为 2.97 分，满足小于 3 分的验收要求。
在敦煌舞验证集上，同一动作按优秀、良好、一般三档扰动生成序列，校准后总分分别落在 95.8—97.2、89.6—92.9、83.6—85.5 区间，三档之间保持稳定区分度，说明评分对动作质量变化敏感且单调。
3.6 语义增强与知识库
语义增强层不直接“看视频”，而是抽取 6 张均匀分布的关键帧，连同量化评分、DTW 距离、节奏 BPM 与命中率、知识库教学要点组成上下文，调用方舟 /responses 接口。返回结果解析为教师分析、学员分析、节奏一致性与建议列表，写入评分报告 JSON 的 semantic 节点，前端在报告页以四段式卡片呈现。
知识库按角色域隔离，支持文档入库、分词检索、自动归集与备份。AI 问答先检索知识库再生成回答，调用日志记录命中条数与耗时，既提升回答可靠性，也满足教学内容的可追溯要求。
3.7 前端交互与可视化
• 评分报告页采用三栏栅格：左栏总览与分项分，中栏五路视频同步对比与实时节奏曲线，右栏部位热力图、关键帧与语义点评。
• 五路视频（教师原片、教师骨架叠加、学员原片、学员骨架叠加、对比成片）共享一条主时钟，播放、暂停、跳转严格一致。
• 关节偏差热力图使用 Canvas 实时渲染，随播放进度更新各部位着色，并以 3D 光照填充模型呈现肌肉轮廓与体积感。
• 实时节奏曲线以 ECharts 静态层叠加 DOM 进度层实现，点击曲线任意位置可跳转到对应视频时刻。
• 三端界面统一采用敦煌矿物色系与壁画纹理，桌宠助手在三端常驻，支持多轮对话与操作确认。

五、应用价值
5.1 教学价值
系统把教师从“反复看视频、凭经验说问题”中解放出来：课后十分钟内即可得到分部位诊断、最差关键帧、节奏对齐情况与改进建议，学员也能看到“哪里不对、差多少、怎么练”。量化的进步曲线使教学效果可跟踪，有利于形成“提交—反馈—改进—再提交”的学习闭环。
5.2 文化传承价值
敦煌舞动作语汇复杂、口传心授成分高。作品将标志性动作转化为可回放的骨架资产与可比较的评分维度，为敦煌舞的数字化保存、课堂辅助教学与大众认知提供了低成本工具，对非遗舞蹈的传播具有积极意义。
5.3 机构运营价值
课程、排课、报名、缴费、考勤、作业、考级与统计在同一套系统中闭环，排课冲突自动拦截、考勤与课消自动联动、续课率按统一口径计算，减少人工台账与口径争议，为小型艺术培训机构提供可负担的数字化底座。
5.4 可迁移性
评分流水线与业务平台解耦，替换参考动作与部位权重即可迁移到中国舞、民族舞、体育训练、康复动作评估等场景；知识库与智能体框架也可复用于其他培训品类。
